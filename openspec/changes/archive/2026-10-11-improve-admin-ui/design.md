# Design

## Context

See proposal.md - Why. Current state shaping the approach:

- `AgentDbWeb.Layouts.admin/1` (`lib/agent_db_web/layouts/live.ex`) is the whole HTML document for every `/admin/*` page: a `flex` row with a fixed `w-56` white sidebar (`.admin-sidebar`) and a `flex-1` content column (`.admin-content`). There is no header bar. Tests assert `class="admin-content` and `id="flash"` hooks.
- `AgentDbWeb.AdminComponents.sidebar/1` lists the five pages and marks `@active`; `@active` is assigned once in `AgentDbWeb.Admin.connect/2` from each page's `@admin_page`. Realtime subscribe/coalesce/refresh lives in `Admin` and must not change.
- Styling is Tailwind utilities in HEEx plus a small `assets/css/app.css`; the served file is generated by the documented `mix assets.build` (prod: `mix assets.deploy`). Any new class must survive Tailwind content scanning. `assets/js/app.js` has an empty `hooks: {}` LiveSocket with no custom JS.

## Goals / Non-Goals

**Goals:**
- Persistent header bar on all console pages (identity + current-page title + sidebar toggle) without new data loading.
- Sidebar hide/show for full-width content, session-persistent, without full reload, working across all five pages and the document editor.
- Colorful but clean refresh of section cards, headers, and status colors with no information removed.

**Non-Goals:**
- No new pages, routes, auth, store access, or realtime-lifecycle changes.
- No per-user theming, dark mode, or full responsive-mobile redesign — collapse is the only layout mode change.
- No component API redesign beyond additive attrs/classes.

## Decisions

### 1. Header lives in the admin layout, title derived from `@active`

Render the header inside `Layouts.admin/1` above the sidebar/content row: brand mark "AgentDb" + environment-agnostic title mapped from the existing `@active` atom (`:overview` → "Overview", etc., Documents active for the editor), plus a `<button>` toggle. No new assigns or facade calls — the layout already receives `@active` and `@flash`.

Alternative considered: per-page `<h1>`-driven header — rejected because pages already render their own `<h1>` headings and the shell must be identical on every page including the editor.

### 2. Sidebar collapse is client-side state (JS + `localStorage`), not a LiveView assign

A tiny vanilla JS snippet in `assets/js/app.js` (no new dependency): toggle button flips a `data-sidebar="hidden"` attribute on the shell root, toggles `hidden` on `<aside>`, expands `<main>`, sets `aria-expanded`, and persists `"admin-sidebar"` in `localStorage`; on `DOMContentLoaded` and `phx:page-loading-stop` (covers `live_session` soft navigation) it re-applies the stored value with default shown.

Why not a LiveView `handle_event` in `AgentDbWeb.Admin`: server state resets on every page change unless pushed into the session, adds a roundtrip for pure UI chrome, and risks re-triggering `load/1` section reloads. Client state keeps `Admin.connect` untouched and satisfies "persists across pages without reload".

### 3. Theme via existing Tailwind utilities + small `app.css` additions

Keep all component function signatures; change only classes: white cards stay but gain a 3px colored top accent per section kind (indigo overview, emerald storage, amber queue/runtime, sky documents/skills), card headers get a subtle tinted background (`bg-<color>-50/60`), status values reuse the existing `.badge-*` palette extended to health/model/queue states, and page content gets consistent `space-y-6 p-6` rhythm. New custom classes (`.admin-header`, `.admin-card-accent-*`, sidebar transition) go in `assets/css/app.css` and the generated bundle is rebuilt with `mix assets.build`.

Alternative considered: per-section `variant` attr with a palette map — rejected as over-abstraction; fixed per-component accents are simpler and match the one-component-per-section structure.

### 4. Accessibility preserved by construction

Toggle is a real `<button>` with `aria-controls="admin-sidebar"` and `aria-expanded`; sidebar keeps `<nav aria-label="Console">`; hiding uses the `hidden` attribute so screen readers follow visibility; focus stays on the toggle; color is never the only signal (labels + text remain).

## Risks / Trade-offs

- [Risk] Tailwind purges a new utility class because it only appears in a string-built class → Mitigation: use literal class names in HEEx; verify with the stylesheet test (`admin_stylesheet_test`) after `mix assets.build`.
- [Risk] Existing tests match `class="admin-content` / sidebar links / `data-active` → Mitigation: keep those hooks byte-identical; add classes alongside, never replace.
- [Risk] `localStorage` unavailable (private mode) → Mitigation: try/catch, default to sidebar shown; feature degrades to per-click toggle.
- [Risk] "More color" becomes noisy → Mitigation: accents limited to header strip + status text; body stays white/gray; palette reviewed in the implementation PR screenshots.

## Migration Plan

No data migration. Deploy is a normal release: merge HEEx + CSS + JS, run `mix assets.build` (CI runs `mix assets.deploy`), run `mix test test/agent_db_web/live/`. Rollback is a plain revert; sidebar state in `localStorage` is inert under the old shell.

## Open Questions

- None. Exact accent hues will be picked at implementation time from the existing Tailwind palette and shown in review.
